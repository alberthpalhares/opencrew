# Glossário — Linguagem Ubíqua

> Termo novo entra aqui ANTES de aparecer no código ou num prompt. A coluna `Contexto`
> diz em qual camada o termo vive: **CLI** (`bin/`, `src/`) ou **Runtime** (`templates/`).

| Termo | Termo no Código | Contexto | Definição |
|---|---|---|---|
| Crew | `crew` | Runtime | Equipe de agentes que produz um tipo de conteúdo; vive em `crews/{code}/` com `crew.yaml` e `pipeline.yaml` |
| Agente | `agent` | Runtime | Persona com papel definido (`*.agent.md`); pode estender um agente base de `_opencrew/agents/` via `extends:` |
| Passo | `step` | Runtime | Unidade do pipeline executada por um agente, inline ou como checkpoint |
| Passo irreversível | `side_effects: irreversible` | Runtime | Passo cujo efeito sai do projeto e não se desfaz (publicar, enviar e-mail, postar); sempre no fim do pipeline, depois do Review e da aprovação final, e nunca repetido automaticamente |
| Verificador automático | `verificar.mjs` | Runtime | Script que mede o texto antes do revisor (tamanhos, hashtags, placeholders, termos proibidos, afirmações a confirmar) usando os `constraints:` dos best-practices; a última linha diz o estado: `VERIFICACAO:OK`, `VERIFICACAO:BLOQUEADA` ou `VERIFICACAO:AGUARDANDO_USUARIO` |
| Bloqueio | `VERIFICACAO:BLOQUEADA` | Runtime | Falha objetiva do verificador (acima de um máximo, placeholder, termo proibido); força REJECT na revisão. `[PREENCHER]` também aparece como bloqueio no relatório, mas, quando é o único tipo, o estado é `VERIFICACAO:AGUARDANDO_USUARIO`: não força REJECT e a aprovação final pede o dado ao usuário |
| Alerta | — | Runtime | Ponto a conferir (abaixo de um mínimo, afirmação em 1ª pessoa com dado); não bloqueia, mas limita a nota a 7/10 e aparece na aprovação final |
| Peça | módulos `verificar/pecas.mjs` e `entrega/` | Runtime | Trecho de uma saída que tem limite próprio no formato: título, meta description, legenda, hashtags, slides, post ou tweet. Cada formato tem uma peça principal (título no blog; legenda ou slides no Instagram; post; tweet). Na entrega, a peça é também o que vira arquivo do canal (`legenda.txt`, `post.txt`, `tweet.txt`, `seo.txt`), e entram as que o verificador não lê: primeiro comentário do LinkedIn, cada tweet de uma thread, assunto, prévia e corpo de e-mail, mensagem de WhatsApp, artigo e palavra-chave do blog. Um cabeçalho de nível 1 sob o qual há outro cabeçalho candidato à mesma peça é o título do arquivo, não uma peça |
| Formato declarado | `caminho=formato` (opção `--arquivo` do `verificar.mjs`) | Runtime | Formato que o runner informa para cada arquivo verificado, tirado do `format:` do passo que o gerou; diz ao verificador quais peças procurar. `--formato` não conta como formato declarado |
| Não medido | linha `Não medido — …` do relatório | Runtime | Limite que o verificador não conseguiu medir: peça principal não achada num formato declarado (alerta), peça sem limite numérico no formato, ou formato que o verificador ainda não mede (sem nível). Conta no resumo e aparece na aprovação final; nunca é dito como aprovado |
| Não verificado | linha `Não verificado — …` do relatório | Runtime | Item da lista que o verificador não leu: arquivo que não existe, pasta ou erro (alerta), ou arquivo que não é texto, como imagem e `.docx` (sem nível, fora do resumo) |
| Nota informativa | seção `**Notas:**` do relatório | Runtime | Aviso no fim do relatório do verificador que não é bloqueio, alerta nem "não medido" e não entra no resumo (ex.: overlay local sem `constraints:`, variável `{{…}}` em e-mail). Não confundir com a nota que o revisor dá |
| Ciclo de revisão | `max_review_cycles` | Runtime | Uma passada do revisor num passo com `on_reject`. O máximo é `max_review_cycles` (padrão 3); se a última passada permitida também rejeita, o runner para e pergunta ao usuário |
| Marcador de dado faltante | `[PREENCHER: …]` | Runtime | O que o agente escreve no lugar de um dado real que não tem; a aprovação final pede ao usuário |
| Fontes do projeto | `fontes:` (crew.yaml) | Runtime | Arquivos/pastas do projeto do usuário que a crew lê a cada run e trata como verdade (caminho relativo à raiz) |
| Conferência de fontes | `conferir-fontes.mjs` | Runtime | Script que confere, no início do run, se os arquivos citados pela crew existem e sugere o novo caminho quando foram movidos |
| Overlay local | `_opencrew/best-practices.local/` | Runtime | Best-practices do usuário (aprendidas ou criadas), lidas antes das do core e nunca tocadas pelo `update` |
| Checkpoint | `checkpoint` | Runtime | Passo que para e pede decisão do usuário |
| Execução | `run` | Runtime | Uma passada completa do pipeline de uma crew; identificada por `run_id`, saída em `output/{run_id}/` (o registro da execução, as pastas de versão de cada passo e, depois da aprovação, a entrega). Fica **aberta** até o `fechar`; aberta e parada, é a que o retomar continua |
| Registro da execução | `execucao.json`, `execucao.mjs` | Runtime | O que uma execução deixa em disco, na pasta dela: tema, situação (aberta, aprovada, rejeitada, abortada, publicada), os passos conferidos com o arquivo de cada um e os marcos. Só os scripts gravam (`caminho.mjs pasta` e `conferir --passo`, `execucao.mjs marcar` e `fechar`); a IA nunca lê nem escreve o arquivo. É dele que saem a linha do `runs.md` e o retomar |
| Pedido (pedido avulso) | `/opencrew pedir <crew> "<tarefa>"`, `caminho.mjs pasta --pedido` | Runtime | Uma tarefa só, feita por um agente da crew fora do pipeline dela. É uma execução sem pipeline: tem pasta e registro próprios (`tipo: pedido`), passa pelo verificador e pela aprovação do usuário, é entregue pelo `entregar.mjs` e entra no `runs.md` com o tema começado por "Pedido: ". Não publica nem envia, e usa um agente só |
| Marco | `execucao.mjs marcar` | Runtime | Um fato da execução gravado no registro: a resposta de um checkpoint (`aprovado`, `corrigido`, `pulado`) ou o veredito da revisão (`aprovado`, `rejeitado`), com a nota da correção. O score do histórico é contado pelos marcos: checkpoints aprovados sem correção ÷ checkpoints respondidos |
| Retomar | `/opencrew retomar <crew>`, `execucao.mjs retomar` | Runtime | Continuar a execução aberta mais recente de uma crew, com o mesmo `run_id`, do passo seguinte ao último feito; revisão rejeitada volta ao passo do `on_reject`, e passo cujo arquivo sumiu é refeito |
| Escritório | `escritorio.mjs` + `_opencrew/core/escritorio/` | Runtime | Página local, em pixel-art, que mostra a crew trabalhando (uma mesa por agente). O servidor escuta só em `127.0.0.1` e só lê. Desligado por padrão: liga com `/opencrew dashboard`, que grava a preferência `Dashboard: enabled` |
| Estado da execução | `crews/<crew>/state.json` | Runtime | Retrato da execução em curso de uma crew: status da execução, passo atual, status e último rótulo de cada agente e a última passagem de bastão. Gravado só pelo `estado.mjs`, e só com o Escritório ligado; o Escritório apenas lê (não confundir com a Execução, que é o run em si) |
| Evento de estado | `estado.mjs <crew> <evento>` | Runtime | Aviso que o runner dá, com um comando por momento, e que muda o estado da execução: `iniciar`, `passo`, `checkpoint`, `pular`, `concluir` ou `falhar`. A última linha diz o resultado: `ESTADO:OK`, `ESTADO:OK — estado recriado` ou `ESTADO:IGNORADO — <motivo>`; nunca para a execução |
| Passagem de bastão | `handoff` | Runtime | Momento em que um agente termina e o seguinte começa. É gravada pelo próprio evento `passo` (não existe evento `handoff`) e, no Escritório, aparece como o boneco de quem entregou levando o papel até a mesa de quem recebe |
| Skill de envio | `side_effects: irreversible` no SKILL.md | Runtime | Skill do catálogo que publica ou envia para fora do projeto (`instagram-publisher`, `blotato`, `resend`): mostra a prévia e só age depois da palavra do usuário |
| Caminho da execução | `caminho.mjs <crew> <ação>` | Runtime | Caminho de um arquivo dentro de uma execução: o caminho declarado no passo (`inputFile`, `outputFile`) com o `run_id` logo depois de `output/` e, na saída, a pasta de versão seguinte do grupo (`v1`, `v2`…). Quem calcula é o `caminho.mjs`, não a IA: `pasta` cria a pasta da execução, `saida` diz onde o passo grava, `entrada` acha a versão mais nova que tem o arquivo e `conferir` confere o arquivo gravado (com `--passo`, o arquivo aprovado entra no registro da execução). A última linha diz o resultado: `CAMINHO:OK`, `CAMINHO:FALTA` ou `CAMINHO:REPROVADO` |
| Entrega | `entregar.mjs` + pasta `entrega/` | Runtime | Pasta `crews/<crew>/output/<run>/entrega/` que o script monta com os arquivos aprovados de uma execução: uma pasta por canal, texto pronto para colar e um `LEIA-ME.md` que diz o que fazer com cada arquivo. É refeita do zero a cada chamada e fica fora do git; o que está pronto é copiado para o destino da entrega. A última linha diz o resultado: `ENTREGA:OK`, `ENTREGA:COM_RESSALVA` ou `ENTREGA:INCOMPLETA`. Quem monta a lista de arquivos é o runner (`prompts/entrega.prompt.md`) |
| Canal | `platform:` do best-practice | Runtime | Onde uma peça será usada. Vem do `platform:` do best-practice do formato do arquivo (o do overlay local antes do do core). São oito pastas na entrega: `instagram`, `linkedin`, `blog`, `email`, `whatsapp`, `twitter`, `youtube` e, desde a 1.10.0, `documentos` (o canal `documento`, do formato `documento-oficial`); arquivo sem formato, ou de formato sem canal conhecido, vai para `outros/` |
| Bloco de serviço | `NOTES`, `NOTE`, `CHECKLIST`, `FORMAT`, comentário HTML | Runtime | Trecho de uma saída que é recado para quem produz, não conteúdo; nunca vai para arquivo de canal |
| Pendência | linha em `## Antes de usar` do LEIA-ME | Runtime | O que impede um canal de estar pronto na entrega: bloqueio do verificador no arquivo de origem, `[PREENCHER]` ou item da lista que não existe. O canal aparece como "Não está pronto" (os arquivos dele são gerados em `entrega/` mesmo assim, mas não vão para a cópia) e o final é `ENTREGA:INCOMPLETA`. Alerta e "não medido" não são pendência |
| Ressalva | `ressalvas.json` + `--aceitar-pendencias` | Runtime | Pendência que o usuário aceitou ("Entregar assim mesmo"). Fica gravada em `crews/<crew>/output/<run>/ressalvas.json`, presa ao arquivo de origem, ao item do verificador e ao trecho; aparece no começo do LEIA-ME ("Entregue com ressalva:"), o canal passa a "Pronto, com ressalva" e é copiado. Mudou um dos três, ou a pendência sumiu e voltou, é pendência nova: a ressalva só vale enquanto a pendência existir sem interrupção. Quando toda pendência é ressalva, o final é `ENTREGA:COM_RESSALVA` |
| Destino da entrega | `entrega.destino` no `crew.yaml` · `--destino` · `--lembrar-destino` | Runtime | Pasta do projeto que recebe a cópia da entrega, uma subpasta por execução (`<destino>/<run_id>/`). É perguntada uma vez por crew e gravada pelo script no `crew.yaml` (com `.bak`); `nao` = não copiar. Tem de ser um caminho relativo, dentro do projeto e fora de `_opencrew/`, `crews/`, `skills/`, `.git/` e `node_modules/` |
| Reentrega | pasta `<run_id>-reentrega-N` | Runtime | Cópia nova de uma execução cuja entrega mudou depois de copiada: vai inteira para `<destino>/<run_id>-reentrega-2` (depois `-3`…), ao lado da anterior, que fica como estava e ganha um aviso na primeira linha do LEIA-ME. Nada copiado é sobrescrito. "Mudou" é em relação ao que foi copiado (o retrato em `copia.json`, na pasta da execução), não ao que o usuário editou na cópia |
| Editáveis | `entrega/editaveis/` | Runtime | HTML que tem, na lista da entrega, uma imagem de mesmo nome (`slide-01.html` e `slide-01.png`): a fonte do slide, para quem quiser ajustar |
| Documento Word | `documento.mjs` + `/opencrew documento <arquivo>` | Runtime | Arquivo `.docx` que o script gera a partir de um texto em markdown (`.md` ou `.txt`) do projeto, com as mesmas palavras e os mesmos números, na mesma ordem. Sai ao lado do texto, com o mesmo nome (ou onde `--saida` disser); na entrega, em `entrega/documentos/`. Um `.docx` diferente que já existe só é trocado com `--substituir`. A última linha diz o resultado: `DOCUMENTO:OK`. O gerador é próprio, sem dependência, e não usa o Word para gerar |
| Perfil de documento oficial | `_opencrew/_memory/documento-oficial.md` · `--criar-perfil` · `--perfil` · `--sem-perfil` | Runtime | Arquivo de texto do projeto, um por projeto, com linhas `chave: valor`, que guarda o papel timbrado: logotipo, três linhas de cabeçalho, rodapé, número de página, margens, fonte e tamanho do corpo. Nasce do modelo do pacote (`_opencrew/core/modelos/documento-oficial.md`) por `--criar-perfil`, só se não existir; quem preenche é o usuário, ou a IA a pedido dele. O `update` não toca nele. Perfil inválido não gera documento: a mensagem diz a linha |
| Timbre | `word/header1.xml` (módulo `documento/timbre.mjs`) | Runtime | O cabeçalho do papel timbrado, repetido em todas as páginas: o logotipo (PNG) à esquerda e as três linhas do perfil à direita, com uma linha preta embaixo. Só existe quando o perfil tem logotipo ou alguma linha de cabeçalho. O rodapé (texto do perfil e "Página X de Y") não faz parte do timbre |
| Marcação de documento | `::: titulo` · `::: subtitulo` · `::: quebra-de-pagina` · `::: assinaturas` … `:::` | Runtime | Linha do markdown que começa por `:::` na primeira coluna e pede o que o markdown comum não tem: título e subtítulo centralizados, página nova e bloco de assinaturas (`Nome \| Cargo`, uma pessoa por linha). Nomes sem diferenciar maiúsculas nem acentos. Qualquer outra palavra depois de `:::` não é marcação: a linha fica como texto, com aviso |
| Aviso de conversão | seção `Avisos:` do relatório do `documento.mjs` | Runtime | O que o gerador diz que não converteu como pedido: imagem não incluída, linha com marcação desconhecida, bloco de assinaturas sem o `:::` final, caractere inválido removido — cada um com a quantidade. Não muda o resultado nem o código de saída; na entrega aparece em `Atenção:`, no LEIA-ME. Não confundir com o Alerta do verificador |
| Nome seguro | seção do runner | Runtime | Caminho que pode entrar num comando: letras, dígitos, espaço e `. _ - / \ : ( )`; com outro caractere o runner não monta o comando |
| Não conferido | alerta da conferência de fontes | Runtime | Citação de caminho de rede ou de endereço de site: a conferência não acessa a rede, avisa e não para a execução |
| Skill | `skill` | Runtime | Capacidade externa (`skills/<nome>/SKILL.md`, às vezes com `scripts/`) que um agente pode usar |
| Best-practice | `best-practice` | Runtime | Guia por formato ou disciplina em `_opencrew/core/best-practices/`, indexado em `_catalog.yaml`; a versão do usuário mora no overlay local, que o runner e o verificador leem antes da do core |
| Tier da crew | `tier` | Runtime | Profundidade do pipeline: Express / Standard / Full (não confundir com o tier project-standards do repo) |
| Sistema | `system.md` | Runtime | Definição completa do runtime; fonte: `templates/AGENTS.md`, instalada em `_opencrew/core/system.md` |
| Ponte | `bridge` | CLI | Arquivo fino por IDE que aponta para o sistema; gerado de `src/lib/ides.js` |
| Texto legado | — | CLI | Texto que as versões até a 1.2.2 gravavam como arquivo inteiro nas pontes sem marcador; o `update` o retira, com cópia, quando está idêntico ao gerado |
| Bloco marcado | `opencrew:start/end` | CLI | Trecho delimitado por marcadores que o CLI pode regravar sem tocar no resto do arquivo do usuário |
| Workspace | `workspace` | CLI | Projeto do usuário com o OpenCrew instalado (`_opencrew/core` + stamp de versão) |
| Payload | `templates/` | CLI | Tudo o que o `init` copia para o projeto do usuário |
| Stamp de versão | `.opencrew-version` | CLI | Versão do OpenCrew instalada no workspace |
| Manifesto | `_opencrew/manifest.json` | CLI | Registro (caminho → hash) dos arquivos que o OpenCrew entregou, gravado pelo `init`, pelo `update` e pelo `init --repair-bridges`; é por ele que o `update` distingue o arquivo que o usuário editou do que só está antigo; registra também cada bloco marcado e que o `.mcp.json` já foi entregue (não confundir com o `crew-party.csv`, o manifesto de agentes de uma crew) |
| Cópia de segurança | `.opencrew-backup/<data>/` | CLI | Pasta onde o `update` (e o `init --repair-bridges`) guarda, antes de substituir, o arquivo do framework (core, skill do catálogo, ponte de arquivo inteiro) que o usuário editou, o arquivo inteiro cujo bloco marcado ou texto legado vai mudar, e o `.mcp.json` antes de ser regravado — ou, sem manifesto, todo arquivo diferente do pacote novo; o resumo do `update` e o do `init --repair-bridges` listam o que foi copiado |
| Conserto (de crew) | `conserto.mjs`, `/opencrew repair` | Runtime | O que leva a uma crew já criada as melhorias que vieram depois dela: o script lê a crew, lista os achados e, com `--aplicar`, grava um item por vez com cópia `.bak`; a IA só conversa e nunca grava em `crews/` |
| Achado (do conserto) | `[código]` na saída do `conserto.mjs` | Runtime | Um ponto que falta numa crew (`formato`, `fontes`, `proibicao`, `manifesto`…); uns o script grava com a resposta do usuário, outros só se resolvem editando a crew |
| Formato da crew | `_opencrew/core/formato-da-crew.md` | Runtime | A definição única dos arquivos de uma crew (`crew.yaml`, `pipeline.yaml`, frontmatter dos passos, `id` do agente); Build, runner e conserto seguem esse arquivo, e as formas antigas continuam sendo lidas |
| Texto livre (formato) | `format: texto-livre` | Runtime | Formato do passo cujo texto não é de rede nem vira Word (proposta, minuta que vira HTML ou PDF, plano, relatório interno): não tem limite de tamanho, a entrega o leva inteiro para `outros/`, e só valem as checagens gerais do verificador (placeholder, proibição, dado a preencher) |
| Núcleo do runner | `_opencrew/core/runner.pipeline.md` | Runtime | O que toda execução de crew usa: nome seguro, inicialização, carga do agente, caminho de saída, o laço de cada passo, validação, veto, laço de revisão, entrega e erro |
| Parte do runner | `_opencrew/core/runner/*.md` | Runtime | Bloco do executor que só vale em alguma condição (seleção de agentes, migração de memória, Escritório, tarefas do agente, contrato de saída, fontes pendentes, fim da execução, retomar, correção no checkpoint); no núcleo fica um toco com a condição exata e o caminho, e a IA lê a parte só quando a condição acontece |
| Sandbox | `sandbox/` | Repo | Workspace local do mantenedor para testar o runtime; fora do git |
