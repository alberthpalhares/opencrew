# Uso real do OpenCrew — diagnóstico da jornada

> Data: 2026-10-02 · Versão observada: 1.4.1 (instalada nos projetos) · Método: leitura,
> sem alterar nada, de dois projetos reais onde o mantenedor usa o OpenCrew, mais a leitura dos
> prompts que conduzem cada momento da jornada.
>
> Este repositório é público: os projetos aparecem anonimizados. Nenhum texto de cliente ou
> dado pessoal foi copiado — só o **tipo** de defeito e onde ele aparece.

## Os dois usos observados

| | Projeto A | Projeto B |
|---|---|---|
| Negócio | Estúdio de foto/vídeo corporativo (B2B) | Associação cultural sem fins lucrativos |
| Crew | Blog SEO + carrossel Instagram + post LinkedIn (7 agentes, 13 passos) | Reforma de documentos institucionais (5 agentes, 7 passos) |
| Uso | **1 execução** completa (~56 min), resultado nunca usado; crew desenhada para rodar toda semana | **8 semanas** de uso intenso; resultados viraram documentos oficiais e foram enviados à diretoria |
| Skills usadas | busca web, image-creator | só busca web |
| O que mais valeu | Pacote completo de um run (blog + carrossel + LinkedIn); a etapa "tendências → sugestões → escolha", acrescentada à mão depois do build | Personas especialistas com papéis claros; memória de decisões e proibições; textos prontos para WhatsApp e e-mail; slides HTML para reuniões |

## A jornada até o 1º resultado (leitura dos prompts)

Estimativa para um usuário não técnico, do `init` ao primeiro carrossel renderizado:

| Métrica (linha de base 1.4.x) | Valor estimado |
|---|---|
| Decisões no chat até o 1º resultado | ~20–30 |
| Turnos de conversa | ~25–40 |
| Tempo | ~45–90 min (Projeto A: ~56 min só de execução) |
| Tokens fixos por execução (runner + agentes) | ~25–35 mil (o tier Express anuncia ~5 mil) |
| Tokens para criar uma crew | ~55–75 mil |
| Passos fora do chat | 6+ (terminal, plugin Playwright, aprovar MCP, Python para renderizar, credenciais da Meta…) |

Atritos principais, na ordem em que aparecem:
1. Instalação e mensagens do CLI em inglês; aviso sobre o plugin Playwright sem explicar como.
2. Onboarding não coleta cores, logo e fontes — os visuais começam genéricos.
3. Criação de crew sem condutor definido (Discovery → investigação → Design → Build) e build
   longo sem retorno de progresso.
4. Execução: tom e seleção de agentes perguntados a cada run; esperas silenciosas; jargão
   ("veto", "pipeline", "checkpoint", "tier").
5. Fim: arquivos em `output/{run_id}/<grupo>/vN/`, legenda dentro do markdown, sem pacote.
6. Publicação automática exige app de desenvolvedor na Meta e token que expira em 60 dias.
